# 权限验证测试说明：班主任赋权给学生班委

## 一、测试环境准备

### 1.1 前置条件
- 已部署最新云函数代码（含auth.js更新）
- 数据库集合：`users`, `user_class_relation`, `student_authorizations`, `student_leader_permission` 已创建
- 准备测试账号：
  - 管理员账号（admin）
  - 班主任账号（head_teacher）
  - 学生班委账号（class_cadre，需已加入同一班级）
  - 普通学生账号（student，需已加入同一班级）

### 1.2 测试班级准备
1. 使用班主任账号创建/确认一个测试班级，记录 `classId`
2. 确认学生班委和普通学生均已加入该班级（`user_class_relation` 中 status='joined'）
3. 确认班级下有学生数据（students集合）

## 六、边界条件测试

| # | 测试场景 | 预期结果 |
|---|----------|----------|
| 1 | 班主任给自己授权 | 不允许（自己已有全部权限，但授权面板不应显示自己） |
| 2 | 班主任给非本班学生授权 | 不允许（saveStudentPermission验证student必须在class内） |
| 3 | 学生尝试给自己增加权限 | 客户端不显示入口；直接调API返回ROLE_DENIED |
| 4 | 管理员(admin)给任意班级学生授权 | 允许（admin有全局权限） |
| 5 | 科任教师(subject_teacher)尝试授权 | 允许（subject_teacher在requireTeacher范围内） |
| 6 | 同时授权多个模块后逐一撤销 | 撤销某模块不影响其他模块权限 |
| 7 | checkPermission查询带class_id过滤 | 同一学生在不同班级的权限互不影响 |

## 七、测试通过标准

- [ ] 班主任可成功授予7类权限（卫生值日/积分/考勤/成长/通知/咸鱼审核/聚光点审核）
- [ ] 被授权学生班委可正常执行所有被授予权限的操作
- [ ] 未被授权学生无法执行需授权的操作
- [ ] 数据严格按班级隔离（除校园咸鱼/树洞/聚光点）
- [ ] 多班级用户必须显式传递classId
- [ ] 权限撤销后立即生效
- [ ] 边界条件全部通过
